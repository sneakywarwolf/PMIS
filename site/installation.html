Installation

Install PMIS with Docker Compose on Linux, macOS or Windows. Follow the steps in order.

Install at a glance

  1. Check prerequisites: Docker, Git and OpenSSL.
  2. Get the source with git clone.
  3. Create the .env file and generate secrets.
  4. Start PMIS from source or prebuilt images.
  5. Check it is healthy, then continue to the remaining steps.

Step 1: Check prerequisites

  • Docker with Compose v2. Docker Desktop on Windows or macOS; Docker Engine with the Compose plugin on Linux. Check with docker compose version.
  • Git, to download the source.
  • OpenSSL, to generate secrets. It is included on Linux and macOS, and in Git Bash on Windows. A PowerShell alternative is given in step 3.
  • A free port for the web interface. The default is 3000.
  • Internet access during installation, to download container images and, if you build from source, npm packages.

Only the web interface port is published on the host. The database, cache, file storage and API stay inside the Docker network.

Step 2: Download PMIS

git clone https://github.com/sneakywarwolf/PMIS.git
cd PMIS

Run every later command from this PMIS folder.

Step 3: Create the configuration file

Copy the template:

# Linux, macOS, Git Bash
cp .env.example .env

# Windows Command Prompt
copy .env.example .env

3a. Set the four required secrets

Open .env and replace each CHANGE_ME with its own long random value: POSTGRES_PASSWORD, MINIO_ROOT_PASSWORD, JWT_ACCESS_SECRET, JWT_REFRESH_SECRET. Use a different value for each.

On Linux, macOS or Git Bash, this fills all four automatically:

for k in POSTGRES_PASSWORD MINIO_ROOT_PASSWORD JWT_ACCESS_SECRET JWT_REFRESH_SECRET; do
  sed -i.bak "s|^$k=CHANGE_ME|$k=$(openssl rand -hex 32)|" .env
done
rm -f .env.bak
grep '=CHANGE_ME' .env || echo "All secrets set"

To generate a single value by hand:

# OpenSSL
openssl rand -hex 32

# PowerShell
$b = New-Object byte[] 32; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); -join ($b | ForEach-Object { $_.ToString('x2') })
Keep .env private and never commit it. If a value contains a $ character, write it as $$. Hex values never contain $.

3b. Choose a MinIO image (required)

PMIS stores templates, reports and screenshots in MinIO. The default image, minio/minio:latest, is no longer available on Docker Hub, so a fresh install fails with pull access denied for minio/minio unless you set another image.

Add a MINIO_IMAGE line to .env naming a MinIO server image from a publisher you trust. The image must include the mc client, because the start-up health check uses it. For example:

MINIO_IMAGE=chainguard/minio:latest
The PMIS stack has been tested to start and pass its health checks with chainguard/minio:latest and with pgsty/minio:latest. Both are third-party builds of MinIO. Review the publisher, and pin a specific version or digest in production.

3c. Optional settings

SettingWhen to change it
ADMIN_PASSWORDSet it to choose the first admin password yourself. If you leave it empty, a random password is generated (see step 6).
FRONTEND_PORT, FRONTEND_URLIf port 3000 is taken, or users will reach PMIS at a different address. FRONTEND_URL must be exactly the address users type in the browser.
COOKIE_SECURELeave false for http://localhost. Set true only once PMIS is served over HTTPS (see Production).
SEED_DEMOLeave false. true creates demo accounts whose passwords are public. Use it only on a private test machine.

Step 4: Build and start PMIS

Recommended: build from source

Builds the web and API images from the folder you cloned and starts everything. The first build downloads npm packages and takes several minutes.

docker compose up -d --build

Alternative: prebuilt images

The only prebuilt release on Docker Hub, version 1.0.0, predates security improvements in the current code. Do not use it. Build from source until a newer release is listed on the releases page.

When a newer release is available, set its version in .env, then pull and start:

PMIS_VERSION=<release version>

docker compose pull
docker compose up -d
If an image is missing locally, docker compose up -d builds it from source automatically. docker compose pull downloads the prebuilt images instead.

Step 5: Wait until all services are healthy

docker compose ps

Wait until backend, frontend, postgres and minio show (healthy), and redis shows Up. On the first start the backend creates the database tables and loads the vulnerability library before it reports healthy.

Step 6: Sign in for the first time

  1. Get the admin password. If you did not set ADMIN_PASSWORD, it was generated and printed once in the log: 
    # Linux, macOS, Git Bash
docker compose logs backend | grep "First login"

# Windows PowerShell
docker compose logs backend | Select-String "First login"
    The line appears only on the start that created the admin account. Store the password safely.
  2. Open http://localhost:3000, or your FRONTEND_URL.
  3. Sign in with username admin and that password.
  4. Set a new password when prompted. The default policy needs at least 14 characters, including an uppercase letter, a number and a symbol.

Step 7: Set up the application

  1. Your profile: open Profile and fill in your full name, phone and designation. Reports use these details.
  2. Users: open Users and create AVPs, Team Leads and Testers. Assign each tester to a Team Lead and each Team Lead to a manager. To add many users at once, download the sample file on the same page and upload it as CSV or XLSX. New users must change their password at first sign-in.
  3. Report templates: open Reports, upload your templates and activate them. Sample Word templates for PCI and VAPT (Web, API, Mobile, Thick Client) are in the Report Template/ folder of the source. They are not loaded automatically. See Reports.
  4. Vulnerability library: the library is preloaded on first start. Admins can extend it or replace it by bulk upload under Vulnerabilities.
  5. Settings: review Settings for session timeout, password policy, retention periods and branding.

Before other people use PMIS, complete the production checklist.

Troubleshooting

SymptomCause and fix
pull access denied for minio/minioMINIO_IMAGE is not set. See step 3b.
set POSTGRES_PASSWORD in .env (or another secret name).env is missing or a required value is empty. See step 3a.
backend keeps restartingRun docker compose logs backend. The most common cause is a JWT secret still set to CHANGE_ME.
minio never becomes healthyThe chosen MinIO image has no mc client. Choose another image (step 3b).
Port 3000 already in useSet FRONTEND_PORT (for example 3001) and the matching FRONTEND_URL, then run docker compose up -d.
No First login line in the logThe admin account already existed, or ADMIN_PASSWORD was set. Use that password.
Sign-in works on HTTPS but not on http://COOKIE_SECURE=true requires HTTPS. Set it to false for plain HTTP on localhost.
"Account is temporarily locked"Too many failed sign-ins. Wait 15 minutes and try again.
A user forgot their passwordAn Admin resets it under Users. The user then sets a new one at next sign-in.
Source build fails while downloading packagesDocker builds need internet access to the npm registry and to cdn.sheetjs.com. Behind a corporate proxy, configure Docker's proxy settings for builds.

Stopping and removing

docker compose stop        # stop, keep everything
docker compose start       # start again
docker compose down        # remove containers, keep data volumes
docker compose down -v also deletes the data volumes, including the database and all uploaded files. This cannot be undone. Take a backup first.

Development setup (contributors)

For changing PMIS itself, not for running it for a team. The database, cache and storage run in Docker. The API and web interface run on the host with npm.

  • Prerequisites: Docker, Git and Node.js 22 (the version the production images use).
  • First-time setup: ./setup.sh on Linux or macOS, setup.bat on Windows. The scripts start the infrastructure from docker-compose.dev.yml, install dependencies, create the database and start both apps. The admin password is printed by the seed step in the same terminal.
  • Windows helpers: start-dev.bat, start.bat, stop.bat, and reset-db.bat to reset development data.
  • Web interface at http://localhost:3000, API at http://localhost:4000.
The development setup uses fixed, local-only credentials and publishes the database, cache and storage ports on your machine. Never use it for real data or expose it to a network.
