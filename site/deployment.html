Deployment

Production Docker stack, local development setup, every configuration variable, and operations.

Production with Docker Compose

Uses docker-compose.yml. Only the frontend port is published. The backend, PostgreSQL, Redis and MinIO stay on the internal Compose network.

  1. Copy the template and fill in the secrets: 
    cp .env.example .env
    Replace every CHANGE_ME value: POSTGRES_PASSWORD, MINIO_ROOT_PASSWORD, JWT_ACCESS_SECRET, JWT_REFRESH_SECRET. Generate each with openssl rand -hex 32. Do not commit .env.
  2. Start the stack: 
    docker compose up -d
  3. Get the first admin password. If ADMIN_PASSWORD is empty, the seed generates one and prints it once when the admin account is created: 
    docker compose logs backend | grep "First login"
    The admin must change the password at first sign-in.
  4. Open http://localhost:3000, or the port set by FRONTEND_PORT.

The backend container runs prisma migrate deploy, then the seed, then starts the server. These steps run on every container start. The seed creates the admin account only if it is missing, imports the catalogue from vulnerabilities.json and skips names already present.

Backend settings not passed to the container

The backend service in docker-compose.yml receives a fixed list of environment variables. The variables below are read by the backend code but are not in that list. Setting them in .env has no effect on the production stack unless the backend environment: block is extended.
  • RATE_LIMIT_PER_MIN (default 300)
  • AUTH_RATE_LIMIT_PER_MIN (default 30)
  • HEAVY_RATE_LIMIT_PER_MIN (default 20)
  • MAX_LOGIN_ATTEMPTS (default 5)
  • ENABLE_SWAGGER (set to 1 to expose Swagger in production)
  • NEST_DEBUG_LOGS (set to 1 for verbose request logs)

Application settings (Admin UI)

Settings such as session timeout, password policy, retention periods, storage quotas, the issue-log columns and the easter-egg toggle are stored in the database. Change them in the Settings page or with PUT /settings. Defaults are in apps/backend/src/settings/settings.defaults.ts. Some settings are persisted and returned by the API but are not enforced at every code path that could use them. The defaults file says so in its header comment.

Development setup

Infrastructure runs in containers and the two apps run with npm on the host. Requires Node.js 18 or later and Docker.

  • Infrastructure: docker-compose.dev.yml publishes PostgreSQL (5432), Redis (6379) and MinIO (9000 API, 9001 console) on localhost. It uses fixed local-only credentials that are written in the file. Do not expose these ports to a network.
  • Environment: .env.dev.example is the development template. Setup scripts copy it to apps/backend/.env.
  • Scripts: setup.sh (Linux and macOS) and setup.bat (Windows) start infrastructure, install dependencies, run migrations and the seed, and start both apps. start-dev.bat starts with visible terminals. start.bat starts silently. stop.bat stops everything and keeps data. reset-db.bat is an interactive reset utility.

Admin password in development: setup.sh prints a fixed login hint when it finishes. The seed does not set that password unless ADMIN_PASSWORD is provided, and .env.dev.example does not provide it. Take the password from the backend log instead, or set ADMIN_PASSWORD before the first seed.

Operations

  • Logs: docker compose logs -f backend
  • Stop and start: docker compose stop and docker compose start. Data is kept.
  • Remove containers: docker compose down keeps the named volumes. docker compose down -v deletes them, including the database.
  • Database backup: docker compose exec postgres pg_dump -U pmis pmis > backup.sql
  • File backup: back up the minio_data volume. It holds templates, generated reports and PoC images.
  • Update: set PMIS_VERSION in .env, then run docker compose pull && docker compose up -d.
  • Volumes: postgres_data, redis_data, minio_data.

HTTPS and reverse proxy

  1. Put a reverse proxy (Caddy, nginx or Traefik) in front of the frontend port. It terminates TLS.
  2. Set FRONTEND_URL to the exact public origin, for example https://pmis.example.org.
  3. Set COOKIE_SECURE=true.
  4. Configure the proxy to overwrite the X-Forwarded-For header. The backend trusts this header from private addresses for per-IP rate limits. Without a proxy that overwrites it, clients can spoof it.

Production checklist

  • Four required secrets set, with two different JWT secrets of at least 32 characters.
  • NODE_ENV=production (set by the Compose file).
  • HTTPS in front of the stack. FRONTEND_URL is the exact origin. COOKIE_SECURE=true.
  • The proxy overwrites X-Forwarded-For.
  • SEED_DEMO=false.
  • ENABLE_SWAGGER unset, unless you need Swagger in production. Note that Compose does not pass it through (see above).
  • PMIS_VERSION and MINIO_IMAGE pinned to specific versions.
  • PostgreSQL, Redis and MinIO ports not published. The shipped Compose file already does this.
  • The first admin password recorded, and the password changed at first sign-in.
Images are pulled from Docker Hub by default (PMIS_IMAGE_REPO). The Compose file also defines a build context for each app. Verify which images you run.
