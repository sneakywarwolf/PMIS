Production & operations

Run PMIS for a team: HTTPS, configuration, backups, upgrades and a checklist to complete before go-live.

What runs

docker compose up -d starts five containers on a private Docker network:

ContainerPurposeReachable from outside
frontendWeb interface. Forwards API calls to the backend internally.Yes, on FRONTEND_PORT
backendApplication server. Applies database migrations on every start.No
postgresDatabase (PostgreSQL 16)No
redisSessions, background jobs (Redis 7)No
minioFile storage for templates, reports and screenshotsNo

Data is kept in three Docker volumes: postgres_data, redis_data and minio_data. Docker prefixes them with the project name, for example pmis_minio_data when the folder is named PMIS. Check with docker volume ls.

HTTPS with a reverse proxy

PMIS serves plain HTTP. Put a reverse proxy in front that terminates TLS.

  1. Bind the web interface to the local machine only, so it can't be reached around the proxy. In .env: 
    FRONTEND_PORT=127.0.0.1:3000
  2. Set the public address and secure cookies in .env: 
    FRONTEND_URL=https://pmis.example.org
COOKIE_SECURE=true
  3. Configure the proxy. Example for nginx: 
    map $http_upgrade $connection_upgrade { default upgrade; '' close; }

server {
    listen 443 ssl;
    server_name pmis.example.org;
    ssl_certificate     /etc/ssl/pmis/fullchain.pem;
    ssl_certificate_key /etc/ssl/pmis/privkey.pem;

    client_max_body_size 25m;   # PMIS accepts uploads up to 25 MB

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;   # replace, don't append
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
    }
}
    The proxy must set X-Forwarded-For to the real client address, replacing any value the client sent, as above. Redirect port 80 to 443.
  4. Apply the changes: docker compose up -d.

Sign-in protection settings

The backend container receives only the variables listed above. To change sign-in lockout or request-rate limits, create docker-compose.override.yml next to docker-compose.yml. Compose reads it automatically.

services:
  backend:
    environment:
      MAX_LOGIN_ATTEMPTS: "5"         # failed sign-ins before a temporary lock
      RATE_LIMIT_PER_MIN: "300"       # requests per minute per signed-in user
      AUTH_RATE_LIMIT_PER_MIN: "30"   # sign-in requests per minute per address

The values shown are the defaults. Lower them for stricter protection.

In-application settings

Session timeout (default 15 minutes), password policy, retention periods, branding and report formats are changed by an Admin under Settings. They are stored in the database and recorded in the settings history.

Backup and restore

A complete backup has three parts: the database, the files volume and your .env. Backups contain client vulnerability data. Encrypt them and restrict access.

Commands below are for Linux, macOS or Git Bash, run in the PMIS folder. Replace pmis_minio_data with your volume name from docker volume ls.

Back up

# Database
docker compose exec -T postgres pg_dump -U pmis pmis > pmis-db-$(date +%F).sql

# Files (templates, reports, screenshots)
docker run --rm -v pmis_minio_data:/data:ro -v "$PWD":/backup postgres:16.4-alpine \
  tar czf /backup/pmis-files-$(date +%F).tgz -C /data .

# Configuration (keep with the backup, store securely)
cp .env pmis-env-$(date +%F).bak

Restore

Restoring replaces all current data. docker compose down -v permanently deletes the current database and files. Back up first if you are unsure.
docker compose down -v
docker compose up -d postgres
docker compose ps postgres          # wait until it shows (healthy)

docker compose exec -T postgres psql -q -U pmis -d pmis < pmis-db-YYYY-MM-DD.sql
docker run --rm -v pmis_minio_data:/data -v "$PWD":/backup postgres:16.4-alpine \
  tar xzf /backup/pmis-files-YYYY-MM-DD.tgz -C /data

docker compose up -d

Use the same .env that was in place when the backup was taken.

Upgrading

  1. Back up.
  2. Get the new version: 
    # Prebuilt images: set PMIS_VERSION in .env to the new release, then
docker compose pull
docker compose up -d

# Built from source:
git pull
docker compose up -d --build
  3. Database migrations run automatically when the backend starts. Watch with docker compose logs -f backend until it reports healthy in docker compose ps.

Health and logs

docker compose ps                 # status and health of each container
docker compose logs -f backend    # application log
docker compose logs -f frontend

Admins can also see infrastructure health under Settings.

Production checklist

  • The four secrets in .env are unique random values, and .env is readable only by the operator (chmod 600 .env).
  • PMIS is served over HTTPS. FRONTEND_URL is the exact public address. COOKIE_SECURE=true.
  • The web port is bound to 127.0.0.1, or firewalled so that only the proxy can reach it.
  • The reverse proxy replaces X-Forwarded-For with the client address.
  • Access is limited to your organisation's network or VPN where possible.
  • SEED_DEMO=false. ADMIN_PASSWORD is removed from .env after the first start.
  • The admin password was changed at first sign-in, and each administrator has their own named account.
  • PMIS_VERSION and MINIO_IMAGE are pinned to specific versions.
  • The database, cache and storage ports are not published. Never use docker-compose.dev.yml for production.
  • Backups are scheduled, encrypted and stored off the server, and a restore has been tested.
  • The host operating system, Docker and PMIS are kept up to date.
