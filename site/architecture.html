Request flow

  1. The browser loads the frontend on port 3000.
  2. API calls go to /api/<path> on the frontend. The Next.js rewrite forwards them to BACKEND_URL/<path>. The Docker image sets BACKEND_URL to http://backend:4000.
  3. The backend runs its global guards in this order: JWT authentication (default deny), rate limiting, then role checks. Routes marked @Public skip authentication.
  4. The controller calls a service. Services apply data-level checks such as project access, then use PostgreSQL, Redis or MinIO.
  5. Responses carry Cache-Control: no-store. Authentication is in HTTP-only cookies, so the browser sends them automatically.

In the development setup the frontend and backend run with npm on the host. Only infrastructure runs in containers. See Deployment.

Data model

The schema is apps/backend/prisma/schema.prisma. Main entities:

EntityPurpose
UserAccount, role, team links (assignedTlId, managerId), profile fields, forced-password-change flag, activity and soft-delete fields.
ProjectEngagement with tester and Team Lead, compliance and template settings, report detail fields, and reportVersionCounter.
ReportTemplate, TemplateFieldUploaded templates (Word or Excel), their effective dates and active flag, and extracted placeholders with optional parameter mapping.
ReportGenerationOne row per generation: status (Pending, Completed, Failed), field data, file paths.
VulnerabilityCatalogue entry with severity, CVSS, CVE and CWE, and approval status. Category is Application/API or Network.
VulnerabilityChangeRequestProposed edit to an approved catalogue entry, with before and after data.
ProjectVulnerabilityProject-scoped record created by a scan import. Not visible to other projects.
Finding, PocStepFinding on a project, linked to a catalogue or project-scoped record, with ordered PoC steps.
NotificationIn-app notification with read state and optional link.
AuditLogAction, actor, target, details, IP address and user agent.
AppSettingsSingle row (id singleton) holding all admin settings as JSON.
QuizQuestion, QuizAttempt, QuizUserStatsDaily quiz questions, one attempt per user per question, and per-user points, streaks and badges.
PatternMapScorePattern Map game scores. Kept separate from quiz data.

Enumerations

  • Roles: ADMIN, AVP, TEAM_LEAD, TESTER
  • Project status: NOT_STARTED, IN_PROGRESS, AWAITING_REVIEW, COMPLETED
  • Finding status: DRAFT, SUBMITTED, APPROVED, REJECTED
  • Compliance type: VAPT, CERT_IN, PCI, ASV
  • Template sub-type: WEB, API, MOBILE, THICK_CLIENT, NETWORK, APPLICATION
