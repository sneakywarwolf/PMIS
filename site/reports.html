Reports

How templates are managed, how a report is generated from project data, and how scan results feed into it.

Templates

  • Admins upload a template file with a name, a compliance category (VAPT, CERT_IN, PCI, ASV), a sub-type, a format (WORD or EXCEL), and an effective-from date.
  • Uploaded files are stored in MinIO. The original filename is kept and used as the naming pattern for generated reports.
  • Templates are activated and deactivated explicitly (PUT /reports/templates/:id/activate and /deactivate). Only Admins can do this.
  • Inactive templates can be deleted. The route removes the file, its metadata and its field mappings.
  • Each project records the template it uses (templateId).

Placeholders and field mapping

  • Placeholders are highlighted yellow in the template. The engine extracts them as template fields, each with a normalised name and a category (project information, vulnerability, contact, date, other).
  • An Admin can add a field the extractor missed, rename it, change its category or description, and map it to a canonical application parameter. Parameters are listed by GET /reports/templates/parameters.
  • A field with no explicit mapping falls back to automatic matching against the normalised name.
The README states that activating a template deactivates the previous template for the same category and sub-type. That behaviour was not re-verified in the report service code for these pages.

Generating a report

  1. Preflight: GET /reports/preflight/:projectId lists missing data, such as empty fields or missing profile details, so the user can fix them first.
  2. Queue: POST /reports/generate with a project ID and an optional format. The job runs on a BullMQ queue and the call returns a generation ID.
  3. Poll: GET /reports/generate/:id/status until the status is Completed or Failed.
  4. Download: the completed file is available through a signed link from GET /reports/download. The link carries an expiry time and a signature.
  5. Version: a project's report version is 1.N. The counter is incremented only when a generation completes. Failed generations do not use up a number, and deleting an old report does not cause a number to be reused.

Field values come from the project record, the assigned users' profiles, and the approved findings with their PoC steps. The project's status moves to Completed after generation.

History is at GET /reports/history/:projectId. A report is removed with DELETE /reports/:id, which the project owner or an Admin can do.

File naming and dates

  • The output name follows the naming pattern of the template's original filename, with project values filled in.
  • The {Report Date} parameter uses the Admin setting formatting.reportDateFormat. The default is YYYY-MM-DD.

Scan imports

Nessus

  1. POST /findings/nessus/preview parses a .nessus or .csv export and lists its findings. Nothing is written.
  2. POST /findings/nessus/import imports only the plugin IDs the user selected.

Imported records are project-scoped (ProjectVulnerability). They are not added to the shared catalogue and are not visible to other projects. A plugin ID already imported for a project is not imported again.

Nmap

POST /projects/:id/nmap-import imports an Nmap XML scan into a Network project. Port data is stored on the project.

Issue Log

GET /reports/issue-log/:projectId returns the Issue Log as CSV. Its columns and their order come from the Admin setting issueLog.columns.

Findings and PoC in the report

  • Findings are included in a report when their status is Approved. Ordering is by CVSS score override first, then the catalogue score, both descending.
  • Each finding can carry a CVSS score and vector override. The override is used in place of the catalogue value.
  • PoC steps are numbered. Each step can carry an image, which is embedded in the output.

Limits

  • Uploads are capped at 25 MB (see Uploads and imports).
  • Report generation, template upload, Nessus, Nmap, PoC image upload, Issue Log and exports share a heavy-route limit of 20 requests per user per minute.
