Reports

Reports are filled from your own Word or Excel templates, using data entered once on the project, the team's profiles and the project's findings.

Preparing a template

  1. Start from your organisation's report in Word (.docx), or in Excel (.xlsx) for Network projects. The Report Template/ folder in the source has eight sample Word templates for PCI and VAPT (Web, API, Mobile, Thick Client).
  2. Write each value PMIS should fill in as a placeholder in braces, for example {Client Name}, and highlight it yellow. Only highlighted placeholders are detected.
  3. Keep each placeholder's text together. Don't rename the placeholders in the findings tables. Keep table header rows intact.

Placeholders you can map

After upload, each detected placeholder can be mapped to one of these values. Unmapped placeholders are matched by name automatically.

GroupValues
ProjectApplication Name, App Version, Application Name & Version, Document Version, Client Name, Client Name & Location, Start Date, End Date, Start & End Date, Scope, Application Details & Scope, Build Details, Tools Used, Testing Environment, Testing Type (Black/Grey Box), Testing Type (Platform), Login/Role Types, Nature/Purpose of Application, Testing Limitation, QA Reviewer Name, Mobile Platform, SHA-1 Hash
NetworkScope Exposure (External/Internal), Network Activity Type (VA/PT/VAPT), Total Scope Count, Quarter
Client contactClient SPOC Name, Designation and Email ID (CERT-In projects)
PeopleTester, Team Lead and Manager: name, designation, phone, email
ReportReport Generation Date, Report Date (format set in Settings), Report Name (generated filename)

Two placeholders have special behaviour:

  • {Compliance Status} or {Project Status} prints Compliant or Non-Compliant. When the placeholder is alone in its cell or paragraph, the background is green or red. It stays empty while the project is In-Progress. It also works in headers, footers and the file name.
  • Findings tables (summary and detailed) are filled with one row or block per finding, including PoC steps with their screenshots.

VA and PT sections (Network)

Wrap content that applies only to vulnerability assessment or only to penetration testing in marker paragraphs. Each marker must be on its own line:

{#VA}
 ... VA-only paragraphs and tables ...
{/VA}

{#PT}
 ... PT-only paragraphs and tables ...
{/PT}

A VA project keeps the VA blocks, a PT project keeps the PT blocks, and VAPT keeps both. Page and section breaks on marker lines are preserved.

In Excel Network reports, rows for Scope IP, VA Details, PT Details and Port Scan Result repeat once per record, and {VA Output} holds each finding's Nessus plugin output. In Word Network reports, the Scope and Detail Findings headings start on a new page.

Uploading and activating (Admin)

  1. Open Reports and upload the template. Choose a name, the category (VAPT, PCI, CERT-In, ASV), the format (Word or Excel), one or more activity types, and the effective-from date.
  2. PCI and VAPT templates cover Web, API, Mobile, Thick Client and Network. CERT-In also offers Application, a single template that serves every non-Network project.
  3. Review the detected fields. Add any the detector missed, and map fields to values if the names differ.
  4. Activate the template. Projects of the matching category and activity type then use it.
Activating replaces the previous template. When you activate a template, any active template with the same category and format that covers the same activity types is replaced. If the old template covered only those activity types, it is deleted: its file and field mappings are removed. Reports already generated are not affected. Keep your own copy of every template file.

Inactive templates can be deleted from the same page.

Generating a report

  1. On the project, run the preflight check. It lists missing project details, profile details and findings that are not report-ready.
  2. Choose Generate report and pick Word, or Excel for Network projects. Generation runs in the background, and the page updates when it finishes.
  3. The template is never picked by hand. A project uses the active Word template for its category and Testing Type (newest effective date wins), and is re-pointed automatically if that template is replaced. If none matches, generation names the missing template.
  4. Download the file. Download links expire after one hour. Reopening the report history gives fresh links.

Generation is blocked until both of these conditions hold:

  • The project has at least one finding, or its compliance status is Compliant.
  • Every finding is report-ready: each PoC step has a description and a screenshot. Nessus findings on Network projects are exempt.

Each completed generation gets the next version number, 1.1, 1.2 and so on. Failed attempts don't use a number. The file is named after the template's file name pattern, with project values filled in. The project status becomes Completed, and its retention countdown starts.

Issue Log

From the project, export the Issue Log as CSV: one row per finding. An Admin sets which columns appear, and in what order, under Settings.

History and deletion

Every generation is listed in the project's report history with who generated it and when. Admins, and testers on their own projects, can delete a generated report.
