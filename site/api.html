API reference

Every backend route, grouped by module, with its access rule. Generated from the controllers in apps/backend/src.

Conventions

  • Paths below are backend paths. The browser calls them with an /api prefix, which the frontend forwards. For example, POST /auth/login is called as POST /api/auth/login.
  • Authentication uses the access_token cookie set by /auth/login. Bearer tokens are declared in Swagger, but cookies are the path the frontend uses.
  • Access: Public means no authentication. Signed in means any authenticated user, with no controller-level role restriction. Role names mean the controller accepts only those roles. Service-level data checks apply to every route.
  • Rate limits apply to all routes. Routes listed as heavy on the rate limits section have a lower per-user budget.
  • Interactive docs (Swagger) are served at /api/docs on the backend only outside production, unless ENABLE_SWAGGER=1.
