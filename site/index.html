Overview

PMIS tracks VAPT engagements from project creation through findings, proof-of-concept evidence, vulnerability approval, and final DOCX report generation. It is built around role-based access control so that testers, team leads, AVPs, and administrators see only the data their role permits.

PMIS is a tool for managing authorized security testing. Operators are responsible for lawful use and for protecting the vulnerability and client data they store in it. Software is provided "as is", without warranty.

Roles

Admin

Full access, user management, bulk user and vulnerability CSV upload, admin dashboard.

AVP

Same permissions as Team Lead, plus the admin dashboard with global statistics.

Team Lead

Creates projects, reviews and reassigns testers, approves vulnerability requests.

Tester

Works on own projects, edits own DRAFT findings, requests new vulnerabilities.

Login accepts either username or email. Accounts lock for 15 minutes after 5 failed attempts.

Dynamic report generation

  • Templates are DOCX files with yellow-highlighted placeholder fields.
  • Placeholders are matched by normalized name; fields are filled from project data and user profiles.
  • Templates are organized by compliance type (VAPT, CERT_IN, PCI, ASV) and sub-type (WEB, API, MOBILE, THICK_CLIENT).
  • Only one template per category and sub-type can be active at a time.
  • A preflight check validates required project fields, profiles, approved findings, and the active template before generation.
  • Finding POC images are embedded and resized to a maximum width of 5.5 in.
  • Generated reports are stored in MinIO; generation sets the project status to COMPLETED.

Upload limits: template 10 MB, report generation 50 MB.

Security features

Password hashing

Argon2id; minimum password length 14 characters.

Session tokens

HTTP-only cookies with refresh-token rotation; refresh JTIs tracked in Redis.

Account lockout

5 failed attempts trigger a 15-minute lock via Redis.

Access control

Global JWT and roles guards with default deny; @Roles() decorator.

HTTP hardening

Helmet security headers with CSP; CORS restricted to the frontend origin.

Input validation

class-validator DTOs on API input.

Audit logging

Logins, CRUD operations, and approvals are recorded with IP and user agent.

See SECURITY.md for vulnerability reporting and docs/SECURITY-AUDIT.md for the audit document.

Quick start

Option A — Docker (recommended)

Requires Docker Desktop (Windows/macOS) or Docker Engine with Compose v2 (Linux), about 4 GB RAM and 3 GB disk.

git clone https://github.com/sneakywarwolf/PMIS.git
cd PMIS
cp .env.example .env          # Windows cmd: copy .env.example .env
# Replace every CHANGE_ME in .env (e.g. openssl rand -hex 32)
docker compose up -d
docker compose logs backend | grep "First login"   # shows the generated admin password

Open http://localhost:3000, log in as admin, and set a new password when prompted. First start takes a minute or two while migrations run.

Option B — Development setup

Infrastructure runs in Docker (docker-compose.dev.yml); the apps run with npm. Requires Node.js 18+ and Docker.

# Windows
setup.bat           # first time: installs deps, starts infra, migrates and seeds
start-dev.bat       # dev servers in visible terminals (start.bat = silent mode)
stop.bat            # stop servers and containers (keeps data)
reset-db.bat        # interactive reset utility

# Linux / macOS
./setup.sh

Operations

  • Back up database: docker compose exec postgres pg_dump -U pmis pmis > backup.sql
  • Back up files: back up the minio_data volume.
  • Update: set PMIS_VERSION, then docker compose pull && docker compose up -d.
  • Data persistence: data lives in Docker volumes and survives docker compose down, but not down -v.
  • HTTPS: place a reverse proxy (Caddy, nginx, Traefik) in front of port 3000, then set FRONTEND_URL and COOKIE_SECURE=true.
